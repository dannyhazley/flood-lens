# Checkpoint 6 — Transfer to one independently evaluated land-cover task

**1. Purpose:** Demonstrate reuse on a genuinely different labelled problem without assuming the flood model transfers unchanged.

**2. Applied question:** Which engineering components transfer, and what scientific assumptions must change for a second task?

**3. Why this matters:** This supports broader applied-engineering evidence and makes the boundaries of reuse visible.

**4. Concepts before starting:** Label ontology, independent spatial groups, sensor semantics, multiclass metrics, task contract, adaptation ledger and training versus inference reproduction. Read notes 03 and 07.

**5. Exact ordered tasks:**

1. Phase A, 3–5 h: choose one manageable, explicitly usable land-cover segmentation source with labels beyond water/non-water, recoverable geography and independent spatial groups. Cap source selection at five hours. A scene-classification dataset does not silently become segmentation.
2. Write new input/target/validity/rights contracts. Check acquisition/geographic overlap and any pretrained-data contamination; choose a small supported subset. If no suitable source fits, save the feasibility outcome and a scope decision rather than inventing completed transfer.
3. Phase B, 12–15 h: create a reuse/reconfigure/reimplement ledger. Reuse manifests, raster checks, reporting and experiment structure where their contracts fit. Change bands, label taxonomy, loss, masks and metrics explicitly; train fresh task-specific parameters unless a separate transfer-learning hypothesis is declared.
4. Build one simple second-task baseline and adapt one compact model. Prove tiny-subset learning before bounded training. Do not build a universal plugin framework.
5. Phase C, 12–15 h: freeze the second task’s own spatial train/development/final split and metric policy before selection; run a bounded comparison and lock its independent result. Apply the same test-use discipline as C2–C4.
6. Phase D, 8–10 h: export one georeferenced second-task output and report, compare it with its own reference, and measure actual adaptation time per component. Show what did not transfer.
7. Close with two separately labelled case studies, independent result tables and limits. If only feasibility was achieved, record that state and explicitly decide whether to proceed to product work on the functioning water pipeline.

### C6 build guide — prove reuse with a new contract

The second source remains unselected; do not pretend there is a definitive provider-specific loading recipe before its rights/labels/grid are inspected. The bounded route is clear: one small **land-cover segmentation** dataset, fresh task-specific parameters, independent spatial evaluation and a reuse/change ledger. A failed source-selection gate remains a feasibility result.

#### Specify the adapter before changing shared code

Write a second task record containing input band names/units/order, class IDs/names, ignore code, eligible-mask rules, geographic groups, model output count, loss, metric conventions and export encoding. Check the raw classes with `numpy.unique` and source metadata with the existing Rasterio validator. Reuse immutable asset IDs and audit coverage rules.

**Default multiclass path when the chosen task has K exclusive classes:** input shape B × C × H × W; logits B × K × H × W; target B × H × W of integer class IDs (`torch.long`); output class uses `torch.argmax` across the class axis. Use `torch.nn.CrossEntropyLoss` with an explicit ignore/mask policy. It expects raw logits, not probabilities already passed through softmax. A K-class taxonomy differs from the binary one-logit water task. If the selected task is multilabel rather than exclusive classes, this default is inappropriate; revise the contract before training.

| Component | Keep or adapt | Verification |
|---|---|---|
| Source hashing/manifests | Reuse if schemas fit | Exact second-source identities and terms retained |
| Raster/grid/mask inspection | Reuse, configure source-specific validity | New units/class/ignore values are checked explicitly |
| Dataset adapter | Adapt loading/band mapping and target dtype | One sample and batch match the new contract |
| U-Net | Reuse architecture pattern; replace input/output dimensions and train fresh parameters | Forward produces K channels on the intended grid |
| Loss | Replace binary loss with exclusive-class cross-entropy where appropriate | Ignored cells never contribute; all-invalid is deliberate |
| Evaluation | Reuse counts/report structure; add K × K confusion and per-class measures | Fixed taxonomy order and absent-class policy declared |
| Export/inference | Reuse grid/provenance/failure handling; change class names/codes | Second output reopens geographically with its own legend |
| UI | Not required for this checkpoint | Saved independent report is sufficient |

**Core APIs to revisit:** PyTorch Dataset/DataLoader, `Conv2d` for the changed head, `CrossEntropyLoss`, `argmax`, and the existing Rasterio/NumPy export/count operations. Proposed project responsibilities are `load_landcover_sample`, `validate_task_contract` and the shared training/evaluation functions parameterised by the new task, rather than a separate untraceable notebook.

#### Build the second comparison in order

1. Choose one candidate within the five-hour research cap and verify one small sample before committing to its architecture. Reject nonspatial class-only data unless the task/scope is explicitly revised.
2. Freeze independent spatial/group roles; keep related images together and record any pretrained-data overlap if pretraining is ever introduced. Do not reuse the flood partition IDs or scores.
3. Implement a simple baseline suitable to the source: a training-majority-class map for a minimum reference, and, if justified within budget, a bounded per-pixel feature classifier such as scikit-learn `RandomForestClassifier`. Fit only training pixels sampled by scene/group, record sample cap/seed, and compare on matched valid support. Choose one justified competitive reference rather than every available classifier.
4. Adapt Dataset/normalisation/model head/loss using the contract above. Tiny-subset fit first, then one bounded configuration and independent final evaluation under the same test-use rules.
5. Use `sklearn.metrics.confusion_matrix` with fixed class order or transparent NumPy counts; compute each class IoU as TP/(TP+FP+FN), macro over the **predeclared** eligible classes and spatial groups. An absent class must not vanish opportunistically from the headline.
6. Export one second-task GeoTIFF and readable report. Record components reused unchanged, reconfigured and rewritten, with actual adaptation hours and defects discovered.

**Worked shape check:** a three-band, five-class task on 128 × 128 chips with batch size two has image shape 2 × 3 × 128 × 128, logits 2 × 5 × 128 × 128 and target 2 × 128 × 128. A water model’s single output channel and binary target cannot be reused as though they already mean those five classes.

**CI additions:** keep flood regression fixtures passing and add second-task shape/class/mask/output checks. Good reuse means the new adapter does not silently alter flood semantics. Do not force a shared abstraction that makes both tasks harder to explain.

**Teaching/repetition exercise:** explain the difference between transferable code, transferable weights and transferable scientific evidence. Prepare a one-page “what I would carry into a third domain” checklist, marking every domain-specific assumption that needs new labels or evaluation.


**6. Expected files and evidence:** Second data/task card and manifest, separate split/configs/baseline/model/results, second geographic output, reuse/change and adaptation-time ledger, `docs/checkpoints/C6.md`.

**7. Definition of done:** One different task has usable provenance, an independent split/result and runnable artifacts; reuse and changed assumptions are demonstrated. A feasibility stop is recorded but does not satisfy the independently evaluated transfer claim.

**8. What can go wrong:** Rebranding the water demo, copying water metrics to new classes, treating RGB reflectance as radar, hidden pretrained contamination, or spending the checkpoint hunting datasets.

**9. Genuine blocker:** No feasible usable source with independent references/groups after the cap, irrecoverable labels/grids, or resource requirements outside the bounded experiment. Lower second-task performance is a valid finding.

**10. What to ask Codex:** Review checkpoint 6 only: inspect second-task artifacts and progress, verify its independent evaluation and one output, explain changed semantics, preserve the working flood path and update state/reuse ledger.

**11. Realistic time budget:** 35–45 hours. Learning 5–6; implementation 10–13; scientific analysis 10–13; testing 5–6; documentation 3–4; presentation 2–3. **Optional:** Pretrained-weight comparison or extra land-cover classes only with a separately recorded hypothesis/budget. One second task is enough. See note 13 for cumulative totals and contingency.

**12. Record in the progress log:** Source-selection hours/outcome, independent target/split, component changes, adaptation effort, experiment IDs/results, limitations, final-test exposure and continuation decision.

**13. What can be shown publicly:** A reuse/change table and separately labelled outputs/results from both tasks, if rights permit. Feasibility findings can be shared as such.

**14. What must not be claimed yet:** Do not claim domain independence, universal environmental intelligence, unchanged weight transfer or ecological benefit.
