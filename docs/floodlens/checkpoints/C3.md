# Checkpoint 3 — Compact segmentation model and controlled experiments

**1. Purpose:** Learn whether a small spatial model earns its complexity, using a bounded set of experiments.

**2. Applied question:** Does learned spatial context improve the declared development task compared with the simple baseline?

**3. Why this matters:** This creates independent modelling evidence while preventing unlimited tuning. A trained file alone is not a meaningful scientific result.

**4. Concepts before starting:** Segmentation, U-Net, loss/gradients, epoch/model checkpoint, overfitting, joint augmentation, ablation, experiment provenance and device reproducibility. Read U-Net for the encoder/decoder idea, not as a promised satellite result.

**5. Exact ordered tasks:**

1. Phase A, 8–12 h: introduce PyTorch and one compact U-Net. Use verified band order and shared preprocessing. Confirm loader output dimensions, class values and separate source/label masks on a training fixture.
2. Overfit a tiny training subset. Check finite loss/gradients, masked invalid pixels, joint image/label/mask transforms and categorical resampling. Diagnose a failure here before larger training; tiny-subset success is debugging evidence only.
3. Measure batch loading, peak memory, device and short-run throughput. Estimate full runs including validation/checkpointing. Shrink model/batch/trial count if necessary; do not purchase compute automatically.
4. Phase B, 12–18 h: declare one reference configuration and at most three justified development variants, with a stopping criterion and trial/time cap. Use training-only normalisation/class weights and development-only selection. Save code/data/split/config IDs, seeds and every attempted trial.
5. Train the reference and bounded variants. Save curves, parameters, runtime and failures. Choose one controlled ablation such as VV versus VV+VH or augmentation off/on; keep other factors comparable and disclose residual differences.
6. Phase C, 10–15 h: compare baseline and neural candidates on identical development pixels/metric rules. Repeat selected seeds only if the cap permits and show all planned repetitions. Retain the better justified candidate; do not select only the lucky seed.
7. Export a loadable artifact including architecture, preprocessing, bands/units, task, threshold, provenance and calibration status. Verify fixture inference from the saved artifact and record the pre-final candidate freeze decision.

### C3 build guide — an explicit first segmentation training path

This section tells you what “start ML training” actually means. The default is **PyTorch, a compact U-Net trained from scratch, NumPy/Rasterio loading, masked binary loss, Adam optimisation and local run records**. Do not add a pretrained ecosystem, tracking server or large training framework before this path works.

#### 1. Define one sample before building a model

A dataset sample is a dictionary/record with image, target, source-valid mask, evaluation-valid mask and scene/group ID. The image is float32 with axes **bands × height × width**. The binary target is float32 **1 × height × width**; its ignored cells are replaced with a harmless placeholder only for loss calculation, while the validity mask excludes them. It is not scientifically legitimate to relabel ignored pixels as dry.

With batch size B and two confirmed radar bands, the input shape is **B × 2 × H × W**; logits/target/mask are **B × 1 × H × W**. “Logit” is an unconstrained numeric score; sigmoid later converts it into a water probability. Write these shapes in your loader/model notes and check them at every boundary.

| Component | Core PyTorch API | What it does / result you should inspect |
|---|---|---|
| Dataset | `torch.utils.data.Dataset`, `__len__`, `__getitem__` | Length is eligible samples; indexing loads exactly one sample from the frozen role list |
| Conversion | `torch.from_numpy`, tensor dtype conversion | Float32 bands/targets and boolean masks; no accidental height/width/channel swap |
| Batch loader | `torch.utils.data.DataLoader` | Combines samples into a batch; start `num_workers=0` for understandable errors, shuffle training only |
| Seed/device | `torch.manual_seed`, NumPy RNG; `torch.cuda.is_available`, MPS availability check, tensor/module `to` | Record seeds and chosen device; start CPU smoke checks, then measure supported acceleration |
| Model | `torch.nn.Module`, `Conv2d`, `ReLU`, `MaxPool2d`, `ConvTranspose2d`, `torch.cat` | Shared convolutional parameters produce same-grid per-pixel logits |
| Loss | `torch.nn.BCEWithLogitsLoss` with unreduced pixel loss | Numerically stable binary penalty from logits; use the explicit valid-pixel reduction below |
| Optimiser | `torch.optim.Adam`, `zero_grad`, `step` | Maintains optimisation state and updates weights from gradients |
| Gradient | loss `backward`; `torch.isfinite` checks | Computes parameter gradients; fail/diagnose NaNs rather than hiding them |
| Evaluation | module `eval`, `torch.inference_mode`, `torch.sigmoid` | Disable training behaviour and gradient bookkeeping, then produce probabilities without updates |
| Save/reload | module `state_dict`, `load_state_dict`, `torch.save` / trusted `torch.load` | Persist parameters and declared metadata; use the supported weights-only load option where applicable and never load untrusted bundles |

#### 2. Make preprocessing explicit

Use one preprocessing function shared by training and inference. Verify dB/linear representation first. Fit a per-band mean and standard deviation on **valid training pixels only**, with a recorded streaming calculation and a zero-variance safeguard. Save those numbers. Apply the same transformation to development/final/inference data; no per-scene display stretch enters the model. If clipping is introduced, predeclare its training-derived bounds and scientific reason.

Fill unavailable context consistently after normalisation using a documented neutral value, and preserve the source-valid mask. Fill values can still affect neighbouring convolutions, so inspect predictions near missing edges and declare any conservative exclusion policy before evaluation. Do not let NaN pixels reach convolution and then try to fix the final output.

Begin with whole audited chips at their actual dimensions. If memory demands crops, use a declared training crop size divisible by the model’s downsampling factor and make crops from training scenes only. Validation uses a fixed full-scene/stitching procedure. Apply flips/right-angle rotations jointly to image, target and masks using operations such as `torch.flip` and `torch.rot90`; do not add RGB colour jitter to radar values.

#### 3. Build one small, understandable U-Net

A starting design is three downsampling stages with widths 16, 32 and 64, a 128-channel bottleneck, and a matching decoder. Each stage uses two 3 × 3 convolutions with padding that preserves spatial size and ReLU; 2 × 2 pooling halves size. The decoder upsamples, concatenates the matching encoder feature map along the channel axis, then applies convolutions. A final 1 × 1 convolution yields **one logit channel**, without sigmoid inside the training output.

These are initial engineering choices, not optimised facts. Use dimensions divisible by eight for the first fixture or define explicit padding/cropping. Before training, print a concise shape table at each stage and verify that output H/W match the target. Record parameter count. Do not expand the network simply because an online example has more channels.

**Proposed project functions:** `load_sample`, `fit_normalisation`, `preprocess`, `train_one_epoch`, `evaluate_development`, `save_model_bundle`, `load_model_bundle`. Keep data preparation, weight updates, scoring and artifact writing separately inspectable.

#### 4. Understand one optimisation step

1. Put the model into training mode and move one batch to the chosen device.
2. Clear old gradients. Run the forward pass to obtain logits of the declared shape.
3. Obtain unreduced binary loss. Select/multiply by evaluation-valid pixels and divide the summed valid loss by the valid-pixel count. Never divide by all pixels including ignored regions. If there are zero valid pixels, skip/reject the batch deliberately and log it.
4. Backpropagate the scalar valid loss; inspect that expected parameters have finite gradients. Update with the optimiser.
5. Record loss, valid count and timing. To summarise an epoch, aggregate valid loss sums/counts rather than averaging unequal batches blindly.
6. For development, switch to evaluation mode plus inference mode, do not update weights, convert logits with sigmoid and compute the same event metrics as C2.

Do **not** apply sigmoid before `BCEWithLogitsLoss`; it already combines the required operations. Do not use `torch.no_grad`/inference mode for the training forward pass. An optimiser object existing is not evidence its parameters were updated.

Start Adam with a declared learning rate such as 0.001 as a **trial starting point**, no scheduler and no class weighting until baseline behaviour is understood. If prevalence makes weighting necessary, derive it on training data, record the choice and keep it fixed within the controlled comparison. A new loss is a separate experiment, not a secret repair mid-run.

#### 5. Prove the learning path on a tiny subset

Use one or two training chips, disable augmentation and run a bounded number of updates. Compare the initial and final training loss and a visible prediction. It should move toward fitting those samples; the purpose is to discover wrong bands, masks, labels or gradients. There is no universal loss cutoff that guarantees correctness.

If it does not learn: inspect target values/valid count → output shape → finite loss → nonzero finite gradients → weights changing → learning rate. If this passes but development is poor, investigate generalisation/overfitting instead of repeatedly “fixing” the architecture. Save this diagnostic separately from headline results.

#### 6. Run the controlled experiment

Write `configs/train-water.json` (or one chosen equivalent) with dataset/split IDs, bands, crop/normalisation, architecture, loss, optimiser, learning rate, batch size, seed, max epochs, selection metric, patience and resource cap. A reasonable initial selection policy is highest development macro water IoU with a fixed tie rule; example patience five evaluations and maximum 30 epochs are **starting limits to benchmark**, not required scientific truths. Freeze the policy before the run.

Record every epoch’s training loss, development loss/metrics, elapsed time and selected checkpoint. Save the best-by-policy artifact, not only the final epoch. Run the declared ablation without changing unrelated settings. Use the bounded trial count above; a result losing to Otsu does not grant an unlimited search.

Each run directory should identify configuration, environment/device, code/split/data hashes, seed, log/metrics CSV, selected weights and a brief outcome. The bundle needs preprocessing/threshold/calibration state and task meaning beside `state_dict`. If resuming training, also retain optimiser/epoch/RNG state separately; inference does not need every optimiser buffer.

#### 7. Verify reload and add a fast CI check

Reload the trusted saved weights into the declared architecture, set evaluation mode and rerun one fixed synthetic input. Compare logits/probabilities with a stated tolerance on the same backend. Different devices may need a measured tolerance; never declare bitwise determinism everywhere. Routine CI checks a tiny CPU forward/loss/reload and invalid-mask case, **not** a full training run or GPU benchmark.

**Teaching/repetition exercise:** explain the full path from one manifest row to one weight update and then to a georeferenced prediction. Identify which components would change for three-band optical imagery and which would change for five land-cover classes. Rebuild the tiny training/evaluation pattern later on synthetic data without copying an entire training notebook; explain each responsibility before asking Codex for its implementation.


**6. Expected files and evidence:** Training/task configs, model/preprocessing implementation, experiment ledger, curves and development comparisons, one ablation table, trusted model bundle, `docs/checkpoints/C3.md` and draft model card.

**7. Definition of done:** The learning path works, a saved artifact reloads and infers correctly, bounded experiments are traceable, baseline comparison is fair, and candidate selection is justified without final-test access. A documented neural loss can complete the comparison.

**8. What can go wrong:** Wrong channels, unmasked invalid loss, RGB augmentation on radar, validation influencing fitted scaling, changing many variables in an ablation, treating best-seed output as typical or adding architectures until a headline improves.

**9. Genuine blocker:** The tiny subset cannot learn after data/loss/gradient checks, training cannot fit measured resources, or saved inference disagrees with the training path. Worse development scores are a negative result, not automatically a defect.

**10. What to ask Codex:** Debug or review checkpoint 3 only: inspect real code, logs, current progress and one failing batch/curve; distinguish implementation defects from overfitting, stay within the remaining trial budget, verify artifact inference and update state.

**11. Realistic time budget:** 30–45 hours. Learning 4–6; implementation 10–15; scientific analysis 8–12; testing 4–5; documentation 3–5; presentation 1–2. **Optional:** Selected seed repeats or a small feature classifier within the declared cap. Ensembles, pretraining, fusion and larger backbones require a separate scope decision. See note 13 for cumulative totals and contingency.

**12. Record in the progress log:** Every run and failed attempt, hypothesis, config/hash/seed/device, measured human and compute time, selection rule, ablation changes, fixture output, remaining trial budget and final-test access (normally none).

**13. What can be shown publicly:** Development curves, an honest matched comparison and an actual ablation with readable labels. Include material reused code/Codex assistance in the contribution account.

**14. What must not be claimed yet:** Training is not improvement; development improvement is not final generalisation; a model probability is not validated uncertainty.

**15. LinkedIn/showcase suggestion:** Topic: what the controlled comparison taught. Evidence first: saved runs/ablation; visual: development comparison or curves; supported: exact observed win/loss/inconclusive result; overclaim: “AI outperforms traditional methods everywhere.” Employer review if content refers to work; rights/model-output review for displayed data and artifacts.
