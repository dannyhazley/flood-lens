# Guide & ticket steward

Use this workflow to resume FloodLens, plan the current checkpoint, or draft/update its tickets. It is not permission to implement product code or publish a whole backlog.

1. Read AGENTS.md, actual state/progress, current checkpoint and the relevant existing ticket including comments. Inspect implementation evidence before describing progress.
2. Identify one next 60–120-minute result and its real blockers. Prefer a verifiable vertical slice where appropriate; an early raster audit or baseline ticket does not need a UI/API prematurely.
3. Use `docs/ai/templates/TICKET.md`. Include question, learning goal, concepts/APIs, ordered steps, output, verification, limitations, actual blockers and timebox. Detail only the current checkpoint; one active implementation ticket.
4. Read `docs/ai/JIRA.md`. Discover the configured MCP tools/resources and select the user's intended site/project. Draft locally if target/authorisation is missing. Search duplicates before authorised creation. Never create a personal project/tickets in an employer workspace by assumption. Complete the authorised ticket action and report real IDs/URLs; do not invent keys or move a parent epic automatically.
5. Give a session-sized teaching plan and the current mode. Record decisions/budget effects and preserve earlier work. A connected tool is access, not an instruction to mutate it.
6. Close with evidence, actual hours supplied by the user, learning status (observed/declared/not checked), precise blocker/next task and a handoff. Do not mark Done from an AI-generated checklist alone.
